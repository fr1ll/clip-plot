# Starting Architecture

`clip-plot` is a Python package and command-line tool for turning image embeddings into a static visual similarity viewer. It is a work-in-progress fork of PixPlot, with the embedding step separated from the viewer build so embeddings can be generated, stored, and reused independently.

The codebase is organized around an nbdev workflow: notebooks in `nbs/` are the editable source of truth, and generated Python modules are exported into `src/clip_plot/`.

## Top-Level Structure

| Path | Purpose |
| --- | --- |
| `nbs/` | nbdev notebooks that generate the package modules and README. Edit these for source changes when following the project workflow. |
| `src/clip_plot/` | Packaged Python module used by builds and installs. `pyproject.toml` sets this as the module root. |
| `src/clip_plot/web/` | Static PixPlot-derived HTML/CSS/JavaScript viewer copied into generated output directories. |
| `clip_plot/` | A duplicate generated module tree at the repository root. Treat this as secondary to `src/clip_plot/` because packaging points at `src/`. |
| `tests/` | Integration-style scripts, fixtures, baseline viewer output, and notes on missing coverage. |
| `vendor/` | Notes for vendored dependencies, currently including `annoy`. |
| `README.md` | Autogenerated nbdev project overview. |
| `FEATURE_FLAGS.md` | Viewer-side feature flag notes for `src/clip_plot/web/assets/js/tsne.js`. |

## Packaging And Tooling

The canonical project configuration is `pyproject.toml`.

Key points:

- The package requires Python 3.10 or newer.
- Build backend is `uv_build`.
- Notable direct runtime dependencies include `pydantic`, `pydantic-settings`, `polars`, `pillow`, `transformers`, `timm`, `umap-learn`, `pacmap`, `rasterfairy`, and `pointgrid`.
- Optional Embedding Atlas export support is in the `atlas` extra, using `daft-lts` and `embedding-atlas`.
- nbdev exports notebooks from `nbs/` to `src/clip_plot/`.
- Poe tasks wrap common workflows: `poe sync`, `poe test`, `poe check`, `poe format`, and `poe clean`.
- Pre-commit runs `nbdev_clean` and `nbdev_export`.

There is also a legacy `setup.py`, but packaging configuration in `pyproject.toml` is the modern source of truth.

## Application Surfaces

The project exposes two console scripts:

| Command | Entry point | Role |
| --- | --- | --- |
| `clipplot_embed_images` | `clip_plot.main:embed_im_cli` | Load images, generate embeddings, attach optional metadata, and write a CSV or Parquet table. |
| `clipplot_project_tables` | `clip_plot.main:project_tables_cli` | Build a complete static viewer from either images or precomputed embedding tables. |

Both commands use `pydantic-settings` CLI parsing against `Cfg` in `src/clip_plot/configuration.py`. Environment variables use the `CLIPPLOT_` prefix.

## Core Configuration Model

`src/clip_plot/configuration.py` defines the main settings objects:

- `Cfg` is the root command configuration.
- `Paths` expands image, table, and metadata paths from files, directories, or globs.
- `UmapSpec` controls the reducer choice and dimensionality reduction parameters.
- `ClusterSpec` controls hotspot clustering.
- `ImageLoaderOptions` controls thumbnail, atlas, seed, and maximum image behavior.
- `ViewerOptions` controls output viewer customization such as tagline and logo.

Important input rules:

- `metadata` and `tables` are mutually exclusive.
- `images` and `tables` are mutually exclusive in the projection pipeline.
- Table inputs are expected to include an image path column and an embedding vector column, defaulting to `image_path` and `hidden_vectors`.

## Main Pipeline

`src/clip_plot/pipelines.py` is the orchestration layer. It contains three important flows.

### Embedding Images

`embed_images_pipeline` powers `clipplot_embed_images`.

Flow:

1. Sort input images.
2. Build an `ImageFactory`, which validates images and aligns optional metadata.
3. Generate embeddings through `get_embeddings`.
4. Write a table under `data/tables/` in CSV or Parquet format.

The output table includes standard columns such as `image_path`, `image_filename`, and `hidden_vectors`, plus metadata columns when present.

### Building A Viewer

`project_images_pipeline` powers `clipplot_project_tables`.

Flow:

1. Accept either image inputs or table inputs.
2. If tables are provided, concatenate them with Polars and read image paths plus vectors.
3. If images are provided, generate embeddings directly.
4. Build an `ImageFactory` to validate and normalize the image set.
5. Copy the static viewer from `src/clip_plot/web/` into the output directory.
6. Write thumbnails, resized originals, and atlas images.
7. Write metadata filter files when metadata exists.
8. Generate layouts and hotspots.
9. Write `data/manifest.json` and `data/imagelist.json`, which the browser viewer loads.

The generated viewer is static. Opening the output `index.html` loads data from the generated `data/` directory.

### Exporting To Embedding Atlas

`tables_to_emb_atlas` is an alternate path for table inputs. It computes 2D coordinates and delegates to `src/clip_plot/to_emb_atlas.py`, which prepares images and invokes `embedding_atlas` to export a separate viewer bundle.

This path depends on the optional `atlas` extra.

## Important Modules

| Module | Responsibility |
| --- | --- |
| `src/clip_plot/main.py` | Thin CLI entry points that parse `Cfg` and call pipeline functions. |
| `src/clip_plot/configuration.py` | Pydantic settings and CLI configuration models. |
| `src/clip_plot/pipelines.py` | End-to-end orchestration for embedding, viewer generation, and Embedding Atlas export. |
| `src/clip_plot/embeddings.py` | Hugging Face image feature extraction via `transformers.pipeline`. |
| `src/clip_plot/images.py` | Image loading, validation, metadata alignment, thumbnail/original writing, and atlas generation. |
| `src/clip_plot/from_tables.py` | Concatenates CSV/Parquet inputs and converts non-vector columns into viewer metadata. |
| `src/clip_plot/layouts.py` | Generates alphabetic, grid, categorical, custom, and UMAP-family layouts. |
| `src/clip_plot/reducers.py` | Wraps UMAP, PaCMAP, and LocalMAP 2D reducers. |
| `src/clip_plot/hotspots.py` | Uses HDBSCAN over normalized embedding vectors to produce default hotspot clusters. |
| `src/clip_plot/metadata.py` | Writes metadata sidecars, layout references, hotspot references, `manifest.json`, and `imagelist.json`. |
| `src/clip_plot/web_config.py` | Copies and customizes the static viewer assets. |
| `src/clip_plot/to_emb_atlas.py` | Optional Embedding Atlas export implementation. |

## Data Flow

The main viewer build can start from raw images or precomputed tables.

Raw image path:

```text
images + optional metadata
  -> ImageFactory validation
  -> Hugging Face embeddings
  -> image atlases, thumbnails, originals
  -> layouts + hotspots + metadata sidecars
  -> static viewer output
```

Table path:

```text
CSV/Parquet tables with image_path + hidden_vectors
  -> Polars concatenation
  -> ImageFactory validation
  -> metadata extraction from table columns
  -> image atlases, thumbnails, originals
  -> layouts + hotspots + metadata sidecars
  -> static viewer output
```

The browser-facing output is centered on:

- `data/manifest.json`, which names layouts, atlas directories, point sizes, metadata availability, and hotspot files.
- `data/imagelist.json`, which maps image names and atlas cell positions.
- `data/layouts/*.json`, which contain 2D point coordinates.
- `data/atlases/<plot_id>/atlas-*.jpg`, which contain packed image cells.
- `data/metadata/`, when metadata is present.

## Layout And Clustering

Layout generation happens in `src/clip_plot/layouts.py`.

The default manifest includes:

- `umap`, generated from embedding vectors through the selected reducer.
- `alphabetic`, a simple square grid in input order.
- `grid`, a RasterFairy layout based on the UMAP output.
- `categorical`, when usable `category` metadata exists.
- `custom`, when both configured X and Y metadata columns are present.

Reducers live in `src/clip_plot/reducers.py` and currently support `umap`, `pacmap`, and `localmap`.

Hotspots are generated in `src/clip_plot/hotspots.py` with scikit-learn's `HDBSCAN`. The pipeline clusters normalized embedding vectors, removes clusters covering more than half the dataset, caps the number of clusters, writes a hotspot JSON file, and references it from the manifest.

## Static Viewer

The viewer is not a separate frontend build system. It is a vendored static site under `src/clip_plot/web/`.

`copy_web_assets` copies that directory into the output location and performs small string replacements for:

- package version,
- optional tagline,
- optional custom logo.

Most viewer behavior lives in `src/clip_plot/web/assets/js/tsne.js`. `FEATURE_FLAGS.md` documents two notable flags:

- `useMipmaps`, which selects the image detail strategy.
- `debug`, which enables diagnostic logging and can be set with `?debug=1`.

## Generated Code Workflow

Most Python files in `src/clip_plot/` begin with an nbdev header such as:

```text
# AUTOGENERATED! DO NOT EDIT! File to edit: ../../nbs/...
```

For durable source changes:

1. Edit the corresponding notebook in `nbs/`.
2. Run `nbdev_export`, `poe sync`, or the configured pre-commit hook.
3. Review the generated changes in `src/clip_plot/`.

If making a small emergency fix directly in generated Python, expect it to be overwritten by the next nbdev export unless the notebook is updated too.

## Testing And Quality

Testing and checks are configured in `pyproject.toml`.

Useful commands:

```bash
poe test
poe check
poe format
poe sync
```

Current tests are a mix of notebook tests, pytest configuration, and integration-style scripts in `tests/`. `tests/tests-to-do.md` lists known gaps, including CLI entrypoint coverage and Embedding Atlas output coverage.

The release workflow in `.github/workflows/release-no-publish.yml` builds a wheel on version tags and uploads it to a GitHub Release, but it currently notes that tests are skipped in that release job.

## Contributor Orientation

When changing behavior, start from the pipeline boundary:

- CLI or settings changes usually begin in `nbs/00_main.ipynb` or `nbs/09_configuration.ipynb`.
- End-to-end data flow changes usually begin in `nbs/13_pipelines.ipynb`.
- Image validation or atlas output changes usually begin in `nbs/03_images.ipynb`.
- Layout behavior usually begins in `nbs/05_layouts.ipynb` or `nbs/15_reducers.ipynb`.
- Viewer behavior usually begins in `src/clip_plot/web/`, because those files are static assets rather than generated Python modules.

The safest mental model is: Python builds a static data directory, and the static viewer reads that data directory at runtime.
